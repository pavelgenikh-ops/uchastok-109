## Вертикальная планировка

Четыре террасы с востока на запад:

```
въездная  u 33,0 … 43,99   83,48 → 83,95   навес, ворота, парковка
домовая   u 13,0 … 33,0    81,85 → 82,35   дом, отм. 0,000 = 82,95
садовая   u  4,0 … 13,0    80,30 → 81,15   газон, барбекю
лесная    u  0,0 …  4,0    80,05 → 80,30   рельеф НЕ трогаем, сосны
```

Отметки подобраны по фактическому профилю так, что баланс земли близок к нулю:
выемка ≈237 м³ / насыпь ≈234 м³. **Изменил отметку террасы — пересчитай баланс**
и убедись, что не засыпал корневые шейки существующих сосен.

## `js/geo.js` — рельеф и координаты

| Функция | Назначение |
|---|---|
| `uv2xy(u,v)` / `xy2uv(x,y)` | перевод между системой участка и локальными XY |
| `uAngle()` | угол разворота участка (≈21°) — знак везде «+» |
| `groundZ(x,y,mode)` | отметка земли; `mode` = `'exist'` или `'design'` |
| `groundZuv(u,v,mode)` | то же в координатах участка |
| `designZ(u,v,zNat)` | проектная отметка с террасированием |
| `inPoly`, `polyArea`, `polyPerim`, `pathLen` | геометрия для спецификации |

Рельеф — IDW-интерполяция по 205 отметкам, сетка 0,5 м, два слоя: `terrain.exist`
и `terrain.design`.

## Грабли, на которые уже наступали

| Симптом | Причина | Лечение |
|---|---|---|
| объект развёрнут на 21° к забору | `rotation.y = -uAngle()` | знак всегда «+» |
| объект уехал за границу на свою ширину | точка вставки взята в `v[1]` | группы растут на север, вставлять в `v[0]` |
| забор «уступами и ромбами» | каждая секция садилась на свою отметку | одна линия верха `zMax + H` на сторону, подрезка снизу |
| край мощения в «пиксельных квадратиках» | инстансы обрезались по bbox | класть элемент, только если он целиком в контуре |
| скрытые деревья отталкивают камеру | `raycaster.intersectObjects` игнорирует `visible` | фильтровать по видимости перед пересечением |
| «файл не изменился» | Chrome кеширует ES-модули | версия сборки `?v=<hash>` в импортах + номер в шапке |
| `Cannot access 'X' before initialization` | порядок объявлений в `spec.js` | объявлять до использования |
| крона отрисовалась шаром | новый `cls` без текстуры в `plants.js` | добавить процедурную alpha-текстуру |

## Спецификация

`js/spec.js` — 9 разделов, всё считается из геометрии `design.js` через `polyArea`,
`polyPerim`, `pathLen` и подсчёт точек посадки. Цифры руками не вписывать:
разойдутся с моделью при первой же правке контура.

## Запуск

```
node.exe server.js      → http://localhost:8140
```

Сервер сам считает версию сборки по максимальному `mtime` файлов `js/html/css`
и подставляет `?v=<hash>` во все относительные импорты. Номер сборки виден в шапке
приложения — по нему проверяется, что заказчик смотрит свежую версию.

## Лестницы: как устроено (важно при любой правке)

Число ступеней и длина марша **не задаются в design.js** — их считает `stairSpan(st)`
в `geo.js` по фактическому перепаду: подступёнок ~150 мм, проступь 330 мм. Одна и та же
функция используется в трёх местах, и расходиться им нельзя:

1. `designZ()` — вырезает в рельефе наклонную полосу под марш;
2. `buildWalls()` в `build.js` — ставит ступени, щёчки и накрывку;
3. `spec.js` — считает количество ступеней в ведомость.

Профиль выреза: земля идёт **по низу подступёнков** плюс дополнительная врезка 12 см
в верхней части, сходящая к подножию в ноль. Без неё ступени выступают на 2–6 см,
и газон (он лежит сплошным ковром по всему участку) их полностью топит — в кадре
остаются только щёчки, а марш пропадает.

**Резкость бровки.** Проектная поверхность сглаживается тремя проходами, иначе рвутся
переходы. Сглаживание превращает уступ между террасами в пологий откос — стенка тогда
стоит на склоне и ничего не держит. Поэтому после сглаживания отметки в полосе ±1,4 м
от каждой стенки и по всей длине каждого марша возвращаются к расчётным.

**Существующие деревья.** `treeKeeper()` в `build.js` снимает деревья, попавшие в пятна
застройки, покрытий, **маршей лестниц и полос подпорных стенок**. Без последних двух
сосна вырастает прямо в ступенях и закрывает лестницу кроной — этот дефект уже ловили.
