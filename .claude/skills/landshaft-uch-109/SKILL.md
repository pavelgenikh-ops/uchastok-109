# Участок 109 — ландшафтный проект

Дизайн-проект благоустройства частного участка. Не ролик, не мультфильм — **проектный документ в 3D**,
из которого считается спецификация объёмов.

## Объект

| Параметр | Значение |
|---|---|
| Адрес | СНТ «МАДИО Озерки», уч. 109, массив Токсово, Всеволожский р-н ЛО |
| Кадастровый номер | 47:07:0518004:14 |
| Габариты по факту (DWG) | 43,99 × 25,06 м, ≈1102 м² |
| Дом | проект 304/2026 «Fathers House», тёплый контур 9,89 × 15,40 м |
| Рельеф | 205 фактических отметок из исполнительной съёмки, падение с востока на запад 84,6 → 79,2 м, перепад 5,46 м (≈12 %) |
| Климат | USDA **4b** (зимний минимум −29…−32 °C), безморозный период ~120 суток |
| Грунт | песок/супесь Токсовской камовой гряды: кислый (pH 4,5–5,5), бедный, **дренирующий** |
| Исходный ландшафт | сосновый бор, лесные посадки с генплана сохраняются |

## Система координат — читать до первой правки

Вся геометрия проекта задаётся в паре `(u, v)`, а не в метрах Three.js:

- `u` — вдоль длинной стороны участка: **0 = запад … 43,99 = восток**
- `v` — поперёк: **0 = юг … 25,06 = север**
- перевод — `uv2xy()` в `js/geo.js`; участок развёрнут на угол `uAngle()` ≈ 21°
- в Three.js: `x = X`, `y = Z` (высота), `z = −Y`

**Знак поворота везде один: `rotation.y = uAngle()`.** Минус перед `uAngle()` — это баг
(объект встанет под 21° к забору), такое уже ловили на хозблоке.

**Группы растут на север (−Z).** Точка вставки объекта — его **южный** край: `CARPORT.v[0]`, не `v[1]`.
Ошибка здесь уводит объект за границу участка ровно на его ширину.

## Где что лежит

```
js/design.js   ← ВСЁ проектное решение. Правки вносить сюда, а не в геометрию
   SITE WALLS STEPS HOUSE CARPORT UTILITY BBQ PAVING STEPPING
   BEDS PLANTING LIGHTS IRRIGATION DRAINAGE FENCE CONCEPTS VIEWS
js/build.js    ← сборка сцены из design.js
js/geo.js      ← рельеф (IDW по 205 отметкам), uv2xy, groundZ
js/plants.js   ← кроны cross-billboard с процедурными alpha-текстурами
js/house.js  carport.js  car.js  carmodel.js  furniture.js  materials.js
js/spec.js     ← ведомость: считается ИЗ геометрии, руками объёмы не вписывать
js/app.js      ← сцена, слои, навигация, PDF, карандаш
```

Спецификация пересчитывается автоматически. Изменил контур мощения в `design.js` — площадь
в ведомости изменилась сама. Никогда не править цифры в `spec.js` напрямую.

## Требования заказчика — нарушать нельзя

1. **Никакой мультяшности.** Деревья — cross-billboard с alpha-текстурами, не шары.
   Машины — лофт по сечениям или готовая GLB, не коробки.
2. **Участок не менять.** Границы, площадь и отметки — строго по DWG «План участка
   для благоустройства», не по кадастру (кадастровый контур больше фактического).
3. **Забор** — ровный вертикальный штакетник серого цвета. Верх полотна — **одна прямая
   линия на всю сторону**, штакетины подрезаются снизу по рельефу. Никаких уступов и ромбов.
4. **Подпорные стенки** — ровная верхняя линия, сплошная накрывная плита, в стенке
   оставлен проём под марш лестницы (см. фильтр `gaps` в `build.js`).
5. **Дорожки не обрываются.** Каждый перепад закрыт лестницей, каждый путь имеет начало
   и конец. Маршрут, упирающийся в грунт, — брак.
6. **Мощение кладётся целыми элементами.** Элемент ставится, только если **полностью**
   внутри контура. Обрезка по bbox даёт «пиксельные квадратики» по краю — это брак.
7. **Навес** — справа от въезда, хозблок встроен в его объём под общей кровлей,
   входом к воротам. Стиль Stahlzart: плоская кровля, антрацитовый каркас, деревянная рейка.
8. **Лесные посадки с генплана сохраняются.** Деревья за границей участка не рисуем.
9. **Навигация как в AutoCAD:** зажатое колесо = панорамирование.

## Рабочий цикл

```
правка js/design.js
   ↓
сервер сам поднимет версию сборки (mtime → ?v=hash в импортах)
   ↓
Ctrl+F5 в браузере, сверить номер сборки в шапке
   ↓
проверить по чек-листу ниже
```

Сервер: `node.exe server.js`, порт **8140**. Версионирование импортов обязательно —
без него Chrome кеширует ES-модули и показывает старую версию (на этом уже теряли время).

## Чек-лист перед показом заказчику

- [ ] номер сборки в шапке изменился после правок
- [ ] ни один объект не вылез за границу участка (вид сверху)
- [ ] верх забора — прямая линия на каждой стороне
- [ ] на каждом перепаде > 0,15 м есть лестница или пандус
- [ ] у каждой дорожки есть начало и конец, нет обрывов в грунт
- [ ] края мощения ровные, без обрезанных элементов
- [ ] баланс земляных работ сведён (выемка ≈ насыпь)
- [ ] спецификация пересчиталась и цифры не нулевые
- [ ] проверено в двух режимах рельефа: существующий и проектный

## Что брать из соседних скиллов, а что нет

**`fancy-yard-landscaper`** — берём метод: зонирование (парадная / приватная / хозяйственная),
фазирование по годам, честные сроки смыкания живой изгороди, правило «не сажать вплотную
к фундаменту», расчёт шага посадки по взрослому габариту.
**Ассортимент оттуда не берём** — он написан под зоны USDA 6–8 (Leyland Cypress, Nellie Stevens
Holly, Southern Magnolia в Токсово вымерзают в первую же зиму). Наш список —
в `references/rasteniya-zona-4b.md`.

**`threejs-webgl`** — берём PBR-материалы, InstancedMesh, настройку теней, дисциплину
`dispose()`, борьбу с Z-fighting. Каркас сцены оттуда не переносить: у нас свой,
на чистом Three.js r168 с importmap, без сборщика и без React.
